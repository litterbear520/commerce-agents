anthropics / commerce-agents

一个大脑，两种店员

这个仓库是一份范本：教你怎么用 Claude 给一家店做两个 AI 助理——一个面向顾客，一个面向店员——而且做得安全。

店门口一个，柜台后面一个

shopping-agent 顾客用——找东西、比较、凑方案、放进购物车、问订单和退换货。
merchant-agent 店员用——看销售、改商品页、处理缺货告警、调价做促销、写营销稿。
每个助理有 5 个技能（5 种它会处理的场景），每种一份 SKILL.md。

一句话进来，发生了什么

顾客的消息和固定提示词打包发给 Claude。Claude 只负责想——该调什么工具、怎么回复。真正碰数据的事全部通过工具交给执行器。执行器先过安全门，再调你的后端。结果返回给 Claude 继续推理。

数据怎样流过系统

每轮对话走一条固定管道。固定部分能被缓存（成本降到 1/10），变化部分被围栏包住（模型只把它当资料，不当指令）。模型的判断通过展示型工具调用到达前端——模型只传 ID 和理由，服务端填充真实数据。

同一个核心，三条运行路径

提示词、技能、工具定义、执行器只写一次，放在 core 里。然后可以在三种运行方式上跑——谁来驱动对话循环不同，安全规则和工具行为完全一致。

Claude 说了不算，门口有人查

安全规则写在代码里，不靠模型自觉。每个写操作要依次过三道检查，全部通过才到你的后端。被拦的返回 held 状态，Claude 会自动调整策略，对话不中断。

你只需要接两个接口

核心不认识你的数据库。它只认两个抽象类——StorefrontBackend（11 个方法）和 MerchantBackend（13 个方法）。你把自己的系统包成它们的实现即可。examples/ 里四个行业就是四种写法。

仓库地图

三层：底层是两个角色共用的机制，中间是两个角色各自的 core + skills + 三条运行路径，顶层是四个能跑的行业示例。
