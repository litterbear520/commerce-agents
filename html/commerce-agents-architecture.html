Commerce Agents 系统架构

两个基于 Claude 的电商 Agent——购物助手和商家助手——的完整参考实现。一套提示词、技能和工具合约，定义一次，在 Messages API、Agent SDK 和 Managed Agents 三条路径上运行；四个行业示例展示从目录搜索到库存管理的完整流程。

分层架构

整个系统分四层。上层依赖下层，同层之间不互相依赖。每层是独立的 pip 包，一个机制只在一处定义。

数据流向：模型选择工具 → 执行器做门控、调用后端、围栏结果 → 展示调用由服务端填充实际数据后变成 UI 事件推送给前端。

两个 Agent

每个角色有一套提示词、五个技能、一组工具合约和一个后端接口（部署方实现的唯一 ABC）。

Shopping Agent

购物 Agent

嵌入商家 App，帮助顾客搜索、比较、规划、下单、查询订单和政策。

后端：StorefrontBackend — 购物车操作是唯一的写入；checkout 不下单不收费，只渲染购物车交给宿主。

技能：search-discovery、planning-goals、purchase-research、memory-personalization、customer-care

Merchant Agent

商家 Agent

供运营人员使用的后台助手，解释业绩、维护商品、处理警报、定价促销、草拟营销活动。

后端：MerchantBackend — 所有写入都是暂存提案（stage_*），需人工批准后 apply_change 才执行平台写入。

技能：performance-insights、catalog-listings、inventory-operations、pricing-promotions、marketing-campaigns

三条运行路径

同一个 Agent 定义（提示词、技能、工具合约）在三种运行架构上运行。安全规则在工具调用内执行，三条路径一致。

Messages API Agent SDK Managed Agents
谁驱动循环 宿主应用 SDK 平台
入口 ShoppingAgent / MerchantAgent ClaudeAgentOptions + Toolset agent.yaml + MCP server
特点 参考实现，功能最完整：接地规则、记忆提取、急切工具分发、流式部分 UI、分析委托 SDK 管理循环；接地以预取形式支持；宿主调用记忆提取 平台托管；无接地规则；记忆仅通过工具写入

设计原则

  • 一个模型拥有对话。规则按适用频率放入工具描述、提示词或技能。
  • 静态提示词和工具列表每轮相同字节。每请求数据放在缓存断点之后的围栏块中。
  • UI 是展示工具调用。模型选择组件和 ID，服务端验证并填充实际数据，流式推送为 ui 事件。
  • 第三方内容是围栏数据。写入受来源追踪门和数量上限约束；checkout 不收费；商家写入需人工批准。
  • 核心与行业无关。行业通过 PresentationExtension 添加 UI，其余交给后端实现。
  • 每个机制只定义一次。在 commerce_common 或角色核心中定义，三条路径共享。

详细安全规则表见 docs/safety.md，后端映射指南见 docs/backends.md。
